# GroundLens

LLM과의 다중 턴 협업에서 **확인되지 않은 전제(LLM Ground)가 산출물에 굳어지는 문제**를 다루는 연구 프로젝트. 그라운딩 이론(Clark & Brennan)을 인간-LLM 협업에 적용해, 전제의 검증 상태를 구분·추적·전파하는 시스템과 그 평가로 구성된다.

- **1차 목표 학회**: UIST 2027 (마감 2027-04-02 전후, 공식 CFP 확인 필요)
- **후속**: IUI / CHI 2028, CSCW
- **현재 단계**: 설계 재편 직후. 핵심 측정 도구 구현 중

---

## 문제 정의

LLM은 사용자의 불완전한 발화를 메우려고 해석을 만든다. "여유로운 일정"을 "주말은 비우는 일정"으로, "예산 30만원"을 "숙소는 1박 4만원대"로 구체화한다. 이 해석은 사용자에게 확인받지 않은 채 산출물에 반영되어 굳어진다.

**비용은 조건이 바뀌어 산출물을 고칠 때 드러난다.** 특히 확인된 조건(예산)에서 LLM이 파생한 미확인 해석(숙소 등급)은 처음부터 보이지 않았기 때문에 개정한 뒤에도 살아남는다.

- **Common Ground (CG)**: 사용자의 positive evidence(직접 진술·승인·수정·인터페이스 조작)로 확립된 전제
- **LLM Ground (LG)**: 그런 증거 없이 LLM이 쓰는 전제. 하위 범주는 구조적 결정 / 암묵적 전제 / 용어 해석

## 현재 설계 — 증거 처리 중심 (feedback2.md)

기여의 중심이 **"사용자가 전제를 지정하는 채널"에서 "그 증거를 처리하는 방식"으로** 옮겨 갔다. 제품 메모리(ChatGPT·Claude)가 이미 컨텍스트 편집을 제공하므로, 채널만으로는 기여가 성립하지 않는다는 판단이다.

| 처리 | 하는 일 | 제품 메모리에는 |
|---|---|---|
| **P1 검증 상태** | 항목마다 "사용자 증거로 확인됨"과 "LLM 추측"을 구분하고 증거를 기록 | 없음. 모두 사실로 표시 |
| **P2 사용 추적** | 이번 응답의 어느 문장이 어느 전제에 실제로 기댔는지 측정 | 없음 |
| **P3 수정 전파·반영 검증** | 고친 전제에 기댄 문장과 파생 전제를 찾아 표시하고, 재생성 후 반영됐는지 재검사 | 없음 |

**방법상의 원칙**: 시스템은 LLM에 대해 판단할 때 **자기보고를 판정 근거로 쓰지 않고 행동을 관찰한다.** 그라운딩 이론이 상대의 이해를 "이해했어?"라는 질문이 아니라 관찰 가능한 증거로 판단하는 것과 같은 원리다.

**평가의 주 비교 대상은 메모리식 기준선(B1)** 이다. 사용자가 편집할 수 있고 편집이 다음 주입에 반영되지만 P1·P2·P3가 없는 조건. 이 기준선을 넘지 못하면 논문이 성립하지 않는다.

자세한 작업 지시는 [`feedback2.md`](feedback2.md)에 있다. **이어서 작업할 때 이 문서를 먼저 읽어야 한다.**

## 핵심 측정 결과

### M3 로그확률 채점 — 재생성 방식을 대체한 근거

재생성 기반 개입(A-V3)은 **개입이 없어도** 잡음 바닥이 컸다.

```
greedy(temperature 0), 개입 없이 반복 생성
  잡음 바닥 평균Δ  0.20 ~ 0.32
  위약 평균Δ       0.33
  실제 전제 Δ      0.51 ~ 0.74
```

위약과 실제 전제가 거의 겹쳐서, 필드별 임계값과 구조화 비교를 동원해서야 겨우 기준을 넘겼다(오탐 1.3%, 작동 3/3, 섹션 정확도 62%).

로그확률 방식은 다시 생성하지 않고 **이미 나온 문장의 확률이 조건에 따라 어떻게 변하는지**만 본다.

```
Qwen3-8B bf16, 세그먼트 19개
  채점 1회       0.47s   (재생성은 15s)
  결정성 편차    0.00e+00  (완전 동일)
  위약 전체 Δ    평균 -0.0204, 표준편차 0.1068
```

### 판정 통계 — 제안서 원안의 결함을 수정

feedback2.md M3은 "위약 19개보다 모두 크고(순열 p<.05)" + "BH로 FDR 통제(q<.05)"를 함께 쓴다. **둘을 같이 쓰면 검정이 무너진다.** 위약 19개면 순열 p의 하한이 1/20 = 0.05인데, BH는 가장 작은 p가 (1/m)·q 이하여야 한다. m=50이면 0.001이 필요해 도달 불가능하다.

모의 확인(귀무가설, 세그먼트 50, 위약 19, 4000회):

```
세그먼트별 순열    거짓양성 0.917   ← 92%가 작동으로 오판
max-T(위약 최대값)  거짓양성 0.046   ← 정상 통제
```

→ **BH를 빼고 max-T(Westfall-Young)로 간다.** 비용은 같고 다중비교가 자동 통제된다.

M3의 필수 조건은 **채점 모델과 파트너 모델이 같아야 한다**는 것이다. 파트너가 쓴 문장의 확률을 파트너로 계산해야 의미가 있다. 따라서 로컬 오픈 모델을 쓴다.


## 이어서 작업할 때

### 1. 먼저 읽을 것

`feedback2.md` → `revision_plan.md`의 최근 항목. revision_plan은 역순이 아니라 추가 순이므로 **끝부분**을 본다.

### 2. 현재 작업 지점 — M3 판정 임계값

`exp_m3.py`가 작동 판정 0/3을 낸다. 진단은 다음과 같다.

```
위약 Δ        평균 -0.0204, 표준편차 0.1068
max-T 임계값  +0.5640   ← 위약 평균보다 5.5 표준편차 위
실제 전제     단언 +0.13~0.35 / 반대 +0.35~0.67
```

임계값이 "위약 19개 각각의 최대 Δ 중 최대"라 과도하게 보수적이다. 반대 조건의 최대 Δ(0.665)가 임계값(0.564)을 넘긴 전제가 있는데도, 판정이 **두 반대 조건 모두** 임계값을 넘길 요구하므로 0건이 된다.

검토할 선택지:
- 반대 조건을 둘 다 요구하지 말고 **하나라도** 넘기면 작동으로 볼지(민감도↑, 특이도↓)
- 세그먼트를 더 잘게 잘라 Δ 신호를 키울지
- 위약 수를 늘려 max-T 임계값의 분산을 줄일지
- 단언 조건의 역할을 재검토 — 현재 단언 Δ가 0.13~0.35로 작지 않아 "이미 쓰고 있다"는 해석과 충돌

### 3. 미결정 사항 (연구자 결정 필요)

1. **파트너 모델을 Qwen3-8B로 확정할지** — 현재 임시 선택. 한국어 다중 턴 품질 비교가 W1–2 과제

4. UIST 제출본에 소규모 사용성 관찰(n≈8) 포함 여부

## 주의사항

- **인과·행동 검사 결과를 CG 승격 근거로 쓰지 않는다.** "LLM이 이 전제를 쓴다"는 "사용자와 확인되었다"가 아니다 (feedback2.md 원칙 2)
- **자기보고를 판정 근거로 쓰지 않는다.** 후보 생성과 어블레이션 비교 조건에만 쓴다
- 게이트 기준에 미달하면 기준을 낮추지 말고 수치·실패 사례·원인 추정을 보고하고 멈춘다
- 한글 텍스트는 리터럴 UTF-8로 쓴다. 유니코드 이스케이프를 쓰면 글자가 깨진 이력이 있다
- 콘솔이 cp949라 한글 출력 스크립트는 `sys.stdout.reconfigure(encoding='utf-8')`가 필요하다
